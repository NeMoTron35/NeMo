# Support

## Product and development questions

Start with the in-repository documentation:

- [Quick start](docs/quick-start.md)
- [Troubleshooting](docs/troubleshooting.md)
- [Architecture](docs/architecture.md)
- [Known limitations](docs/limitations.md)

For reproducible bugs, open a GitHub issue using the bug-report template and include the affected route, browser/runtime, steps to reproduce, expected behavior, actual behavior, and non-sensitive logs.

## Security issues

Do **not** open a public issue for suspected vulnerabilities, leaked credentials, signing-boundary failures, or private-key exposure. Follow [SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting/security advisories when available.

Never paste seed phrases, wallet private keys, service-role keys, database passwords, bearer tokens, or unredacted credentials into an issue.
